Option 3 — stacked tags

Type a term, press Enter, it becomes a tag and the box empties ready for the next one. The query string stops being something you look at and edit — the tags are the state, and the query is only how it's written to the URL. Free text is not a special case: it is the keyword field, so every tag has the same shape.

Rules this sets

  1. Enter commits. A complete term becomes a tag and the box clears. The box is never a place where filters accumulate as text.
  2. Tags are the filter state. Nothing else holds it. The query string exists only to put that state in the URL (?q=imported:today category:none) so a view is linkable and survives reload.
  3. Tags are written canonically, whatever you typed. imported date = today and imported:today both land as the tag imported:today — so the terse form is what you learn by reading back.
  4. An incomplete term never commits. category: + Enter opens the value menu instead of making a broken tag.
  5. An invalid term never commits either. The text stays in the box, the field goes red and says why — so you fix it rather than hunt a silent zero-result.
  6. Backspace on an empty box removes the last tag, and clicking a tag puts it back in the box for editing. Nothing is a dead end.
  7. Everything that filters appends a tag — the + Filter builder, a click on a row's category, "review this import". There is one mechanism, and you can always see and remove what it did.
  8. Free text is the keyword field, not an exception. Bare words are sugar — typing sobeys commits as keyword:sobeys — so there is exactly one kind of tag and one commit rule. payee: and memo: stay available when you want to search one column rather than both.
  9. Because nothing filters until Enter, there is no debounce and no as-you-type request. Every keystroke is free; the list changes only when you commit. This is a change from today, where budgeter searches 300ms after you stop typing.
