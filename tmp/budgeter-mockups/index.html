Budget

The problem: a card per group means columns never align, there are no group subtotals, and allocated-versus-spent is three mono columns of mental arithmetic.

direction a
Single ledger
One table, groups as section rows with subtotals, a pace meter per row, allocated edited in place. Best for scanning a column top to bottom.
direction b
Group cards that collapse
Keeps the card-per-group split but the header carries subtotals and a group meter, and groups collapse. Closest to what you have.

Carried across every direction

These are not choices — they are fixes or corrections that apply whichever direction wins.

  • Stop using .stat-label for body copy. v4 uppercases it, so every card description and empty state on the dashboard and settings is currently shouting.
  • Fix the UTC month bug. toISOString().slice(0,7) on both dashboard and budget converts to UTC, so an evening near month-end fetches the wrong month's data while the label still shows the right one.
  • Correct the MCP card. It claims no tools are registered and documents X-API-Key setup; there have been six tools behind OAuth since June.
  • Month state in the page header, shared between dashboard and budget so switching pages keeps the month.
  • Separate fixed bills from day-to-day spending in every pace and projection figure. Rent, insurance, childcare and internet all land on the 1st; a naive daily-average projection is wrong by thousands mid-month.
  • Red only means over-allocation. Today every spending figure is red, so nothing stands out.
  • Replace alert() with showStatus / dsConfirm, and sentence-case the JS-set button labels ('saving', '✓ saved').

What I need from you

Pick per page — mixing is fine and expected, the pieces are deliberately independent.
